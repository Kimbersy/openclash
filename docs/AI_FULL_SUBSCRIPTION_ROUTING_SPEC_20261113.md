# AI 全订阅候选池、地区分组、速度与稳态切换（候选设计，未部署）

状态：2026-11-13 需求正式扩展；**只有架构设计，不代表功能已上线或节点已通过AI业务验收**。

## 用户最新硬约束

1. **全订阅**：候选不能从现有 `🤖 AI` 的13个策略组成员中反向枚举。必须覆盖 OpenClash 当前**所有启用并参与合并/生效的机场订阅源**中的每条节点，包括内嵌 `proxies`、通过 `proxy-providers` 引入的节点、现有全部国家及未知名称节点。不假定今日58个就是永远节点总数，也不从磁盘全部旧配置中擅自混入停用订阅。
2. **地区可指定**：全局AI自动和各地区AI稳态分组并存。用户选择指定地区时，自动切换不能跨出此地区；没有合格备用就提示，不偷偷跨地区。地区优先参考双源真实出口国家；标签与真实出口不一致时按真实出口归类、保留差异标记。尚未验证真实出口的节点暂列待核验，不冒充已确认国家。
3. **速度可衡量**：节点健康与AI业务资格是硬门槛；在合格候选间综合近期连接成功率、超时率、实际RTT/p95、（如安全可测）小文件吞吐和业务响应时间、倍率/流量成本，优先稳定且足够快。只在初选或需备援时排序；**当前节点健康不因另一条更快而切换**。
4. **服务独立**：ChatGPT/Gemini/NotebookLM分别建`usable/unusable/unknown`记录及有效期；普遍200/204、地理IP、单一TCP/TLS握手均不代表登录、长对话、上传、生成成功。403/429/官方服务故障须分类，避免整组误切。三服务共用AI组只有在实际兼容时启用；否则逐服务细分，并审查Google共享登录会话策略。
5. **防抖切换**：只有当前节点连续独立故障、合格备用最近健康，才允许切；带故障计数、去重、多目标确认、冷却、最短驻留和原主线恢复后的不自动回切。人工指定地区/节点的显式意图高于自动控制，只有用户选择具体受控子组才可自动切换该组。
6. **正式单核心**：生产仅一套OpenClash/Mihomo；可测试时临时第二核心，结束必须退出并最终精确清理所有历史孤儿目录、日志、脚本及不必要守护器。现有AI.list、网页、YouTube、Disney+、Worker/KV和其他分流不得回退。

## 信息来源与全量覆盖验收

| 数据源 | 如何读取 | 边界 |
|---|---|---|
| OpenClash成功更新/合并后的**当前生效**私有YAML | 读取`proxies`，只在私有本机目录管理完整参数指纹 | 避免只抓父AI13项，也不读取已停用/历史YAML作为当前来源 |
| `proxy-providers` 引用 | 枚举全部现行provider，并用运行中控制API只读`GET /providers/proxies`核对已加载节点 | provider仅有定义不等于内容已成功加载；API结果应与配置权限一致 |
| OpenClash配置的所有已启用订阅源 | 核对更新成功、合并来源、有效订阅数和来源ID；只输出匿名源数/节点数/冲突数 | 如果有源未进入现行合并结果，标记`INCOMPLETE`并禁止声称“全量筛选成功” |
| 动态更新 | 原始快照+每个完整节点定义的私有指纹（所有协议字段）对比 | 同名换地址/端口/密钥/传输不得复用旧服务合格状态；更新不等于立即切当前健康连接 |
| 检测事实 | 服务资格、真实出口、RTT分位数、成功率、吞吐（可选）、时间、数据源、用户手动回执 | 密钥/订阅URL/节点服务器/实际IP不进入公开GitHub/聊天；未知不得冒充通过 |

**特别提示**：用户已经取得实机`AI_GROUP=YES TYPE=select CONFIGURED_MEMBERS=13`，这13是顶层策略组的选项数；之前UCI活动配置58个内嵌节点也仅是某个时间点和合并快照。既不能拿13代表全节点，也不能假定只有58个或只一个机场源。需先把`enabled source count / merged embedded count / provider count / loaded provider nodes / conflicts / missing`全部以匿名回执核实，才能宣称覆盖所有订阅。

## 可操作的UI分组模型（候选，只有有合格节点的地区才呈现）

```text
🤖 AI                      [原父select，旧成员保留，人工选择权]
  ├── 🛡️ AI·全局稳态       [合格服务池；可跨地区，当前健康不抢线]
  ├── 🇹🇼 AI·台湾稳态       [严格TW实测出口，不越区]
  ├── 🇯🇵 AI·日本稳态       [严格JP实测出口，不越区]
  ├── 🇸🇬 AI·新加坡稳态     [严格SG实测出口，不越区]
  ├── 🇺🇸 AI·美国稳态       [严格US实测出口，不越区]
  ├── 🌐 AI·其他已验证地区 [按实测国家动态创建更多地区或可选汇总]
  └── [现有全部原组/手动选项保持顺序及回退]
```

每个地区受控组本身用`select`作为控制器操作对象（不使用`url-test`自动抢更低延迟节点，也不使用普通`fallback`自动抢回首选）。用户仍可以手工进入组选择某个节点，控制器必须识别手动修改并暂停该组自动改写，直至明确恢复AUTO。指定日本时只能选日本验证成员；如果只有一条合格日本节点，必须明确“没有备用”，不能暗中切美国。全局组允许跨区，但需有可解释的首选地区/稳定度/成本政策。

**按服务路由的后续扩展**：若无法找到可同时满足ChatGPT、Gemini、NotebookLM的足够多节点，则拆`🤖 ChatGPT`/`🤖 Gemini`/`🤖 NotebookLM`对应独立服务合格池和地区选择。新组不允许粗暴取代原`AI.list`里的共享`accounts.google.com`或Google关联请求；必须在候选配置中做路由归属测试和真实登录会话回归，再逐步上线，不要一口气创建所有“服务x地区”冗余的UI选项。

## 排序与切换解耦

资格优先：在同一服务和地区集合内筛`observed_country_verified + service_verified + subscription_fingerprint_current + sufficient_recent_health`。对分服务组，按对应服务验证；全服务共用组则需满足所声明服务集的交集。不可因名字或地理吻合直接准入。

排序优先序（指标有数据时）：持续服务成功率/近期故障与超时 → RTT p95与实际业务响应 → 可选吞吐能力 → 高倍率、流量成本和跨源故障关联性；不承诺任意固定毫秒或MB/s阈值。指标缺失标`unknown`而不是0，避免错排；至少预留来自不同线路/提供者的备份。

控制状态：`MANUAL > HEALTHY > SUSPECT > DEGRADED > SWITCH > COOLDOWN`。健康时不因测速结果变化切换；短时错误复核；发生可信连续网络/业务故障且最近验证备节点才切一次；若整个平台异常或403/429分类不属于节点网络故障，则暂停盲目轮换。保持单个`select`子组的当前节点，冷却期与最短驻留不自动回切；仅在当前节点真正持续坏且备节点可靠的紧急情形例外。
